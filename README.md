# ドカン！お祈りメールクラッシャー

就活の「お祈りメール」やライブの落選メールでモヤっとした気持ちを、ゲームでスカッと発散するアプリです。

## ターゲット

- 就活のお祈りメールをもらってモヤっとしている学生
- ライブの抽選に落選してモヤっとしている学生

## 利用環境

モバイルブラウザ

## 遊び方の流れ

1. **タイトル画面**
   - タイトルが表示される
   - モヤっとしたメールの文章を貼り付ける入力フォーム（アプリ連携ではなく直接コピペ）
   - 「スタート」「遊び方」などのボタン
   - 「スタート」を押すとゲーム画面に移動
2. **ゲーム画面**
   - 入力したメールの文字が1文字ずつブロックに描かれ、壁のように積み上がっている
   - ポケモンGOのボール投げのように、球をブロックに投げつけて崩していく
   - 奥行き（3D演出）を出すかどうかは実装しながら判断

## 画面遷移とメール本文の受け渡し

```
TITLE → 「スタート」 → MAIL_INPUT → 「ゲーム開始」 → GAME
```

- `src/scenes/MailInputScene.js` がメール本文入力画面。ブロックの生成は一切行わず、
  入力文字列をトリムしたものを `onStartGame(mailText)` で渡すだけに徹している。
- `src/main.js` の `App.goTo()` が `onStartGame` の戻り先として
  `GameScene.setMailText(mailText)` を呼んでから `mount()` する
  （`ResultScene.setScore()` と同じ「mount前にsetterで値を渡す」パターン）。
- `GameScene._setupTower()` が実際のブロック生成場所。積む文字は
  `_buildCharacters()` が返す配列に一本化してあり、`this.mailText` が未設定（`null`）の
  場合（「遊び方」から直接ゲームへ進んだ場合など）もランダムな文面を同じ手順で
  1文字ずつに分解する。つまり「1文字=1ブロック」の経路は常に1本だけ。

### 改行・空白の扱い

`GameScene._buildCharacters()` 内で `replace(/\s+/g, '')` により、
半角/全角スペースや改行はすべて除去してから1文字ずつブロックに割り当てている
（句読点はそのままブロックになる）。分割は絵文字などのサロゲートペアを割らないよう
`Array.from()` を使う。また `MAX_MAIL_BLOCKS`（現在24文字）を超える
入力は先頭から切り詰めてタワーが大きくなりすぎないようにしている。

## ブロックの文字表示

ブロックに書かれた文字は DOM のオーバーレイではなく、`CanvasTexture` として
ブロックの面そのものに焼き込んでいる（`src/game/Block.js` の
`createCharacterTexture()`）。文字がメッシュの一部になるため、ブロックが崩れて
回転しても文字が追従し、手前のブロックが奥の文字を正しく隠す。

- 文字を貼るのは手前(+Z)と背面(-Z)の2面のみ。残り4面は紙の断面色。
  `BoxGeometry` のマテリアル配列は `[+X, -X, +Y, -Y, +Z, -Z]` の順。
- 同じ文字のテクスチャは `GameScene` の `characterTextures` で使い回している。
  ブロック間で共有しているので `Block.dispose()` では破棄せず、
  `GameScene.unmount()` でまとめて破棄する。
- テクスチャの解像度（448x288）はブロック手前面の縦横比 1.4:0.9 に合わせてある。
  ブロックの実寸を変えるならこの比率も一緒に直さないと文字が潰れる。

### 次に触るべき場所（ゲーム担当者向け）

- ゲーム画面のブロックは「紙」の見立て（クリーム色の下地＋墨色の文字）で、
  タイトル画面の背景（`src/game/TitleBackground.js`）のレンガ調とは配色が別。
  世界観を統一するかは未対応。
- タイトル背景のレンガは今も DOM ラベル（`.brick-label`）方式のまま。
  ダミー文字なので実害はないが、ゲーム画面と同じテクスチャ方式に揃える余地はある。
- `HOWTO`（遊び方）からゲームへ直行する導線は残っており、その場合はメール本文が
  ないのでランダム文面が積まれる。`HOWTO → MAIL_INPUT` に変える案は未着手。
- タワーの列数は `Math.ceil(Math.sqrt(文字数))` で決めている簡易実装のままで、
  画面の縦横比を見ていない。カメラも `(0, 9, 14)` の固定値。24文字だとタワー幅が
  8 になり、スマホの縦画面では横にはみ出す。カメラ位置とセットで別ブランチで対応予定。
- `MAX_MAIL_BLOCKS` は、実際のメール文長の分布を見ながら
  ゲームバランス（球数・的の大きさ）と合わせて再調整すると良さそう。
