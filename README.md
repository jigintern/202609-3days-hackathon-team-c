# ドカン！お祈りメールクラッシャー

就活の「お祈りメール」やライブの落選メールでモヤっとした気持ちを、ゲームでスカッと発散するアプリです。

## ターゲット

- 就活のお祈りメールをもらってモヤっとしている学生
- ライブの抽選に落選してモヤっとしている学生

## 利用環境

モバイルブラウザ

## 遊び方の流れ

1. **タイトル画面**
   - タイトルが表示される
   - モヤっとしたメールの文章を貼り付ける入力フォーム（アプリ連携ではなく直接コピペ）
   - 「スタート」「遊び方」などのボタン
   - 「スタート」を押すとゲーム画面に移動
2. **ゲーム画面**
   - 入力したメールの文字が1文字ずつブロックに描かれ、壁のように積み上がっている
   - ポケモンGOのボール投げのように、球をブロックに投げつけて崩していく
   - 奥行き（3D演出）を出すかどうかは実装しながら判断

## 画面遷移とメール本文の受け渡し

```
TITLE → 「スタート」 → MAIL_INPUT → 「ゲーム開始」 → GAME
```

- `src/scenes/MailInputScene.js` がメール本文入力画面。ブロックの生成は一切行わず、
  入力文字列をトリムしたものを `onStartGame(mailText)` で渡すだけに徹している。
- `src/main.js` の `App.goTo()` が `onStartGame` の戻り先として
  `GameScene.setMailText(mailText)` を呼んでから `mount()` する
  （`ResultScene.setScore()` と同じ「mount前にsetterで値を渡す」パターン）。
- `GameScene._setupTower()` が実際のブロック生成場所。積む文字は
  `_buildCharacters()` が返す配列に一本化してあり、`this.mailText` が未設定（`null`）の
  場合（「遊び方」から直接ゲームへ進んだ場合など）もランダムな文面を同じ手順で
  1文字ずつに分解する。つまり「1文字=1ブロック」の経路は常に1本だけ。

### 改行・空白の扱い

`GameScene._buildCharacters()` 内で `replace(/\s+/g, '')` により、
半角/全角スペースや改行はすべて除去してから1文字ずつブロックに割り当てている
（句読点はそのままブロックになる）。分割は絵文字などのサロゲートペアを割らないよう
`Array.from()` を使う。また `MAX_MAIL_BLOCKS`（現在120文字）を超える
入力は先頭から切り詰めて壁が大きくなりすぎないようにしている。

### 上限が120文字である理由

240文字も検討したが、物理演算が持たなかった。cannon-es のステップ所要時間を実測すると:

| 構成 | 中央値 | p95 | 最大 | 衝突後に起きている剛体 |
| ---- | ------ | --- | ---- | ---------------------- |
| 120ブロック（6列×20段） | 2.89ms | 4.47ms | 7.65ms | 121 |
| 240ブロック（8列×30段） | 4.07ms | 8.03ms | 15.87ms | 240 |
| 240ブロック（12列×20段） | 8.17ms | 12.25ms | 20.22ms | 201 |

60fps の予算は1フレーム16.67ms で、これは描画を含まない物理だけの数字。
さらに PC(Node)での計測なのでモバイルは数倍遅い。240だと崩落時に壁のほぼ全部が
一斉に目を覚ますため、フレーム落ちが避けられなかった。
入力欄（`MailInputScene` の `MAX_MAIL_LENGTH`）も同じ120に揃えてあり、
「入力できたのに壁にならない」状態が起きないようにしている。

## ブロックの文字表示

ブロックに書かれた文字は DOM のオーバーレイではなく、`CanvasTexture` として
ブロックの面そのものに焼き込んでいる（`src/game/Block.js` の
`createCharacterTexture()`）。文字がメッシュの一部になるため、ブロックが崩れて
回転しても文字が追従し、手前のブロックが奥の文字を正しく隠す。

- 文字を貼るのは手前(+Z)と背面(-Z)の2面のみ。残り4面は紙の断面色。
  `BoxGeometry` のマテリアル配列は `[+X, -X, +Y, -Y, +Z, -Z]` の順。
- 同じ文字のテクスチャは `GameScene` の `characterTextures` で使い回している。
  ブロック間で共有しているので `Block.dispose()` では破棄せず、
  `GameScene.unmount()` でまとめて破棄する。
- テクスチャの解像度（448x288）はブロック手前面の縦横比 2.24:1.44 に合わせてある。
  ブロックの実寸を変えるならこの比率も一緒に直さないと文字が潰れる。

## 壁の組み方・狙い・距離（`src/game/StageLayout.js`）

「何文字を何列に積むか」「どこから投げるか」「カメラをどこに置くか」は互いに依存するため、
`StageLayout.js` 1箇所にまとめてある。`GameScene` 側には計算を持たせない。

- **列数は画面比から決める。** 縦持ちなら縦長の壁（120文字で6列×20段）、横持ちなら
  横長の壁（12列×10段）が選ばれる。`Math.ceil(Math.sqrt(n))` の固定式だと縦画面で
  横にはみ出していたのを、全列数を総当たりして「壁が最も画面に収まる列数」を選ぶ形に変えた。
- **発射距離とカメラ距離は分離してある。** 発射距離は `mount()` で確定させて以降は動かさない。
  ここを画面比に連動させると、端末を回転させるたびに飛距離が変わり、
  プレイヤーが掴んだ狙いの感覚が無効になってしまう。回転で動くのはカメラだけ。
  カメラは必ず発射地点より後ろに来るよう下限を設けてあり、球がカメラの背後から飛んでこない。
- **ブロックの実寸は元の1.6倍**（`BLOCK_SIZE`）。重力に対して世界が大きくなるぶん
  滞空時間が伸びて放物線と崩落が見やすくなる。距離も比例して伸びるので画面上の見かけは変わらない。
  衝突判定の閾値（`Block.js`）は速度が√1.6≒1.27倍になるぶんを補正してある。

### 狙いの3軸（`src/game/AimController.js`）

| 入力 | 決まるもの |
| ---- | ---------- |
| HUD の `<` `>` 長押し | 左右の向き（ヨー）。可動域は壁幅から自動算出 |
| 画面を手前（下方向）へドラッグ | 仰角。`pullRatio × 45°` の線形 |
| 画面を右へドラッグ | 威力。中央が中間で、左に引けば弱くなる |

以前は指の位置から床面へのレイキャストで左右を決め、縦ドラッグ1本で仰角と威力を
同時に動かしていた。この方式だと**引き量の84%が死に帯域**（手前に落ちるか頭上を越える）で、
「めいっぱい引っ張って壁を壊したい」という操作がそのまま失敗につながっていた。
軸を分離し、壁を高くしたことで、当たる組み合わせは16%→73%になっている。

速度域は距離から毎回計算する（`Ball.launchSpeedRange`）。下限は仰角45°の山なりで
壁の根元にぎりぎり届く速度、上限はほぼ水平に撃って届く速度。
低い仰角と低い威力を同時に選ぶと届かない組み合わせは物理的に残るが、
軌道プレビューの点線が指を離す前に着弾点を見せるので、撃つ前に気付ける。

### 次に触るべき場所（ゲーム担当者向け）

- ゲーム画面のブロックは「紙」の見立て（クリーム色の下地＋墨色の文字）で、
  タイトル画面の背景（`src/game/TitleBackground.js`）のレンガ調とは配色が別。
  世界観を統一するかは未対応。
- タイトル背景のレンガは今も DOM ラベル（`.brick-label`）方式のまま。
  ダミー文字なので実害はないが、ゲーム画面と同じテクスチャ方式に揃える余地はある。
- `HOWTO`（遊び方）からゲームへ直行する導線は残っており、その場合はメール本文が
  ないのでランダム文面が積まれる。`HOWTO → MAIL_INPUT` に変える案は未着手。
- **球数（`TOTAL_BALLS`、現在8発）は未調整。** 120ブロック×耐久2＝延べ240ヒット必要な一方で
  球は8発しかないので、崩落の連鎖に全面的に依存している。「全ブロック消滅でクリア」の判定は
  残してあるが実質はスコアアタック。実際に崩してみて手応えを見てから調整するのが良い。
- ブロック同士の衝突ダメージは速度に比例させていない（一律1）。ボールだけ
  `BALL_DAMAGE_PER_SPEED` で速度比例にしてある。連鎖まで比例させると一撃で全壊しかねないため。
- 1ブロックあたり6面それぞれにマテリアルを割り当てているので、120個で最大720ドローコールになる。
  モバイルで描画が重いようなら、側面4面のマテリアル統合や影の無効化が効くはず（未計測）。
